# 오토로그 시나리오 점검 (2026-11-11 ~ 11-15, v0.5.0 → v0.9.0)

기능을 구현한 뒤 Pleos Connect 에뮬레이터에서 시나리오별로 돌려 본 기록이다.

- 대상: `autolog/` v0.5.0 디버그 빌드(S01~S25), v0.6.0 디버그 빌드(T01~T10), v0.7.0 디버그 빌드(U01~U07), v0.7.1~v0.7.2 디버그 빌드(V01~V04), v0.7.3 디버그 빌드(W01), v0.8.0 디버그 빌드(X01~X06), v0.9.0 디버그 빌드(Y01~Y08)
- 환경: Pleos Connect Emulator v2.1.0, AVD `Pleos_Connect_v2.1`, 화면 2560x1440
- 점검 시각: 2026-11-11 19:56 ~ 20:20(v0.5.0), 20:53 ~ 21:05(v0.6.0), 21:26 ~ 21:32(v0.7.0), 2026-11-13 15:50 ~ 16:31(v0.7.1~v0.7.2)
- 방법: Virtual Console HTTP API로 차량 신호를 넣고(`tools/vc.sh`), adb로 화면을 누르고, 앱 로그(AUTOLOG)·화면 캡처·앱 DB·내보낸 파일로 확인
- 단위 테스트: v0.7.2 기준 70건 통과 (상태 머신 14, 용무 제안 10, 장소 10, 운행기록부 9, 엑셀 6, 합치기·나누기·되돌리기·되살리기 18, 월말 안내 3)
- 단위 테스트(v0.9.0): 87건 통과 (위에 더해 상태 머신 15, 빈 구간·짧은 이동 7, QR 코드 4, 폰으로 받기 5)
- 증거 칸의 번호는 점검할 때 찍은 화면 캡처 번호다. 저장소에는 그 가운데 몇 장만 `docs/screenshots/`에, 내보낸 파일은 `docs/sample/`에 실었다

## 이번에 넣은 기능 (v0.4.0 → v0.5.0)

| 기능 | 내용 |
|---|---|
| 첫 실행 안내와 동의 | 기록 항목, 쓰는 곳, 두는 곳과 기간, 음성, 동의하지 않을 권리를 알리고 '동의하고 시작'을 눌렀을 때만 기록을 시작한다. 그 전에는 차량 신호를 구독하지 않고 서비스도 띄우지 않는다. |
| 음성 메모 | 카드의 '음성 메모'를 누르면 SpeechToText SDK(ON_DEVICE)로 한 마디를 받아 비고 메모에 적는다. 12초 동안 들은 말이 없으면 그만둔다. 주행이 시작되면 취소한다. |
| 메모 글자 입력 | 카드에서 비고 메모를 적고 저장한다. 목록과 운행기록부 비고에 붙는다. |
| 정리할 운행 | 미분류가 2건 이상이면 카드 위에 '정리할 운행 N건'과 '제안 N건 모두 수락'이 뜬다. 운행마다 무엇을 제안했는지는 목록에 '제안: 출퇴근'처럼 적힌다. |
| 용무 제안 규칙 | 같은 두 곳을 오간 지난 운행의 분류를 먼저 따르고(방향 무관), 없으면 같은 도착지의 분류를 따른다. |
| 운행 고치기·지우기 | 목록에서 운행을 고르면 카드에서 용무·운전자·메모를 고친다. '이 운행 삭제'는 한 번 더 눌러야 지워지고, 지운 운행은 표시만 해 두고 목록과 운행기록부에서 뺀다. |
| 엑셀 내보내기 | 운행기록부를 .xlsx와 CSV로 함께 쓴다. 차량 저장소의 Download/AutoLog 폴더에 저장한다. 외부 라이브러리 없이 직접 쓴다. |
| 연 누적 | 운행기록부 탭에 그 해의 누적 총주행거리, 업무용 사용거리, 업무사용비율을 보여 준다. |
| 기록 기준 설정 | 문을 열지 않았을 때 기다리는 시간(5·10·15·30분), 기록할 최소 거리(1·2·3km) |
| 자동 시작 | 차량이 켜진 뒤(BOOT_COMPLETED)와 앱 업데이트 뒤(MY_PACKAGE_REPLACED)에 앱을 열지 않아도 기록을 시작한다. |
| 데이터 전체 삭제 | 운행, 내보낸 파일, 차량·운전자 정보, 설정, 동의를 모두 지우고 첫 실행 안내로 돌아간다. |
| 좁은 창 | 앱 영역 1개(폭 약 840dp)에서는 한 열로 놓는다. 운행기록부 표는 옆으로 밀어 본다. |

## 추가로 넣은 기능과 점검 (v0.6.0)

| 기능 | 내용 |
|---|---|
| 장소 이름 | 운행 카드의 '장소 이름'에서 출발지·도착지에 '집', '회사' 또는 직접 적은 이름을 붙인다. 그 자리(반경 150m)에서 출발하거나 정차한 운행은 주소 대신 그 이름으로 보이고, 운행기록부 비고에도 그 이름이 들어간다. 내비 목적지는 이름으로 찾는다. 설정의 '장소'에서 지운다. |
| 좌표 기록 | 운행마다 출발한 곳과 정차한 곳의 좌표, 도착지가 내비 목적지인지를 남긴다(Room v5). 저장된 주소와 목적지 이름은 바꾸지 않고, 화면과 파일에서만 장소 이름으로 바꿔 읽는다. |
| 집과 회사 사이 제안 | '집'과 '회사'로 이름 붙인 두 곳 사이 운행은 지난 기록이 없어도 출퇴근으로 제안한다. 같은 구간을 전에 다르게 분류했으면 그 분류가 먼저다. |
| 운행 추가 | 자동으로 기록되지 않은 운행을 날짜(오늘·어제·그제)와 계기판 거리로 적는다. 주행 전 거리는 마지막 기록의 주행 후 거리, 주행 후 거리는 지금 계기판 거리로 미리 채운다. |
| 기록 안내 다시 보기 | 설정에서 첫 실행 때 동의한 내용을 다시 본다. |

## 마저 넣은 기능과 점검 (v0.7.0)

| 기능 | 내용 |
|---|---|

## 합치기·나누기 되돌리기와 지운 운행 되살리기 (v0.7.1, v0.7.2)

직접 써 보다가 합친 운행을 되돌릴 방법이 없다는 점이 나와서 넣었다.

| 기능 | 내용 |
|---|---|

| 나누기 되돌리기 | 나뉜 두 쪽이 모두 그대로 있을 때, 어느 쪽에서든 누르면 원래 한 운행이 돌아온다. 한쪽을 지웠거나 다시 합쳤으면 되돌리기가 나오지 않는다. |

## 피드백 반영: 하차 전 입력, 짧은 이동 보존, 폰으로 받기 (v0.9.0, 2026-11-15)

제출 전에 받은 피드백 가운데 세 가지가 구현과 주장이 어긋난 곳을 짚었다. 코드에서 사실로 확인하고 고쳤다.

v0.9.0에서 확인하지 못한 것:

- 실제 폰으로 QR을 찍어 받는 것. 에뮬레이터의 주소(10.0.2.15)는 밖에서 닿지 않아 포트 전달로 대신했다. 실차에서 폰이 차량 Wi-Fi에 붙었을 때 차량 화면 기기의 주소로 닿는지는 모른다.
- 문을 열지 않고 대기 시간이 지나 운행이 닫힐 때 골라 둔 용무가 적히는 경우. 문이 열릴 때와 같은 코드 경로지만 돌려 보지 않았다(대기 시간이 최소 5분).
- 폰으로 받기가 5분 뒤 스스로 닫히는 것. 기다려 보지 않았다.
- 계기판 값이 소수로 오는 실차에서 빈 구간 기준 0.5km가 맞는지.
- 좁은 창의 폰으로 받기 패널, 어두운 화면.
- 정차 중에 앱이 죽었다 살아나면 골라 둔 용무는 남지 않는다(저장하지 않음). 운행 자체는 이어서 닫힌다.

## 점검하다 고친 것

1. 정리할 운행 패널이 카드 아래로 밀려 화면 밖에 있었다. 카드 위 한 줄로 옮기고, 운행별 제안은 목록에 적었다.
2. 메모를 저장해도 키보드가 남았다. 저장하거나 용무 버튼을 누르면 키보드를 내린다.
3. 설정을 바꿀 때마다 서비스 시작이 다시 불렸다. 동의 상태가 바뀔 때만 켜고 끈다.
4. 정차 안내가 "운전석 문을 열면"만 말했다. "운전석 문을 열거나 N분이 지나면"으로 고쳤다.
5. 엑셀 파일의 계기판 열이 좁아 머리글이 잘렸다. 열 너비를 넓혔다.
6. 좁은 창의 운행기록부에서 요약이 길어 표가 네 줄만 보였다. 좁은 창에서는 차량 정보를 빼고 연 누적 이름을 줄였다(일곱 줄).
7. (v0.6.0) 좌표를 남기기 전의 운행에서 붙인 장소 이름이 좌표가 있는 새 운행에는 이어지지 않았다. 좌표가 없는 장소는 원래 이름으로 찾고, 다시 이름을 붙이면 좌표를 채우게 했다.
10. (v0.7.2) '지운 운행' 목록에 사용자가 지운 운행이 아니라 나누기를 되돌리면서 사라진 조각이 나왔다. 지운 표시가 붙은 까닭(사용자 삭제, 합치기·나누기, 되돌리기)을 운행에 적어 두고, 사용자가 지운 것만 내놓게 했다.
8. (v0.6.0) 손으로 추가한 운행이 운행기록부에서 계기판 거리 순서와 어긋난 자리에 놓였다. 같은 날 운행은 계기판 거리 순으로 놓는다.
9. (v0.7.0) 앱 데이터를 지우거나 앱을 다시 깐 뒤에는 전에 내보낸 파일을 앱이 지울 수 없어서, 내보낼 때마다 "이름 (1)", "이름 (2)" 파일이 쌓였다. 번호가 붙은 것까지 찾아 지우고 새로 쓴다. 앱이 지울 수 없는 예전 파일 하나는 남는다.

## 알게 된 것

- 에뮬레이터 화면 오른쪽 끝의 창 막대(점 세 개)를 왼쪽으로 끌면 앱이 앱 영역 1개로 줄고 옆에 내비가 뜬다. 폼 팩터 도구 없이 좁은 창을 시험할 수 있다. 재부팅하면 다시 넓은 창으로 돌아온다.
- 에뮬레이터를 재부팅하면 Virtual Console의 계기판 거리가 0km로 돌아간다. 시연 전에 `./tools/vc.sh odo 12340`으로 맞춘 뒤 예시 운행을 넣는다.
- SpeechToText의 ON_DEVICE 모드는 앱 등록 없이 한국어를 인식한다. `sendAudio`로 16kHz·16비트·모노 PCM을 넣으면 마이크 없이 시험할 수 있다(`DemoVoiceReceiver`).
- 출시 빌드에 합쳐지는 권한: `CAR_DRIVE`, `CAR_DOORS`, `NAVI_ROUTE`, `TTS_SERVICE`, `STT_SERVICE`, `RECEIVE_BOOT_COMPLETED`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, 그리고 SDK가 넣는 `android.permission.INTERNET`(TextToSpeech·SpeechToText SDK)과 `VEHICLE_BINDING`(Vehicle SDK). 앱 코드는 네트워크를 쓰지 않는다.
- (v0.9.0에서 바뀜) 최소 거리 미만 이동을 건너뛰면 운행기록부의 계기판 거리가 이어지지 않는 줄이 생겼다. 지금은 짧은 이동도 저장하고, 운행을 지워서 벌어진 자리는 '기록이 빈 구간'으로 알린다.
- 출시 빌드에는 SDK 때문에 이미 `android.permission.INTERNET`이 들어 있었다. v0.9.0의 폰으로 받기는 이 권한으로 차량 안에서 포트를 여는 데만 쓰고, 밖으로 나가는 연결은 만들지 않는다.

## 아직 구현하지 않은 것

- 파일을 메일로 보내기, 세무사무소가 여러 차량의 파일을 한 번에 받기. 서버가 있어야 한다. (v0.9.0) 같은 네트워크의 폰이 QR로 받아 가는 '폰으로 받기'는 넣었다.
- Gleo 음성 명령 연동. 받아 둔 문서에 연동 규격이 없고 에뮬레이터에서 확인할 수 없다.
- 착석 신호. 에뮬레이터에서 값이 반대로 나와 쓰지 않는다.
- 차량 여러 대 구분. 차 안에 설치되는 앱이라 지금은 해당이 없다. 계정으로 기록을 모으게 되면 필요하다.
- 손으로 추가한 운행의 계기판 거리 고치기. 지우고 다시 추가하면 된다.
- 개인정보 처리방침 문서(책임자, 연락처, 처리 위탁 여부). 앱 안에는 기록 안내만 있다.
